# Development panel

Start the local panel from the repository root:

```sh
uv run --locked kusama-dashboard --artifacts artifacts --port 8765
```

Open [the panel](http://127.0.0.1:8765/). The workspace selector scopes projects, continuations, research and sources to an existing artifact store. All artifacts includes recursively discovered runs; select `overnight` or another store to use its registered projects and source corpus. Workspace discovery occurs when the server starts; restart after adding a new store.

- **New run (the home screen):** author an open-ended question, optionally add a title and context, and press **Start run**. The model researches the question and freezes at least three distinct provisional studies; FLUX renders their complete saved compositions and instructions. Qwen inspects the actual images, then can revise or combine saved branches, reopen research from a visible result, reformulate, or pause for human review. Each new image is inspected before another decision. Expand Run settings to choose study/seed-variant caps, initial and reopened research actions, development actions, a named render profile, and time limit. Online collection research is always enabled. The selected limits are displayed before dispatch.
- **Runs:** search names, paths and briefs, filter status, and open a single run workspace. **Run updates** combines research actions, saved images, development choices, execution events, and files/logs with the newest saved updates first. Search the stream or filter by update type; **Show earlier updates** reveals older evidence. Image cards open the saved artwork and expand to its prompt and lineage; research cards expand to the exact saved prompt, response and returned evidence. Prompts and image sidecars stay with their research/image update. Other file saves and execution receipts recorded in the same second are grouped with that update; adjacent remaining file saves within a minute share a compact card, with inline previews and explicit reload controls. File/image/development timestamps are file modification times, not reconstructed execution times; grouped updates use their newest timestamp, and undated evidence appears last. The evidence panel keeps the question, costs, frozen settings, all images, source sessions, branches, decisions, and searchable files available without switching tabs. Parent and source links open the exact corresponding evidence section. Live polling preserves unchanged cards and expanded stream evidence. Historical runs retain their original saved evidence and policies. Status is recorded execution state; pending work may belong to an expired session. Refresh and live polling never start inference.
- **Development:** inspect projects and branches, select an artifact with an operator name and reason, prepare a `ContinuationCreate` request, inspect a frozen continuation, explicitly dispatch an eligible continuation, and record observations or development decisions. Request schemas expand beside the JSON fields.
- **Research:** inspect saved inquiries, tool actions, rejected leads, notebooks, hypotheses, source selections and connection proposals. Detailed evidence loads on demand. Source-context links open whole references, exact detail crops, descriptions, provenance and display permissions; Sources has no separate sidebar tab.
- **Tools & system:** inspect resource deadlines, frozen render profiles, call/token accounting and experiment-memory counts. Prepare independent-research, autonomous-development or research-to-render plans from exact requests. Each existing CLI workflow has a copyable help command and local guide; execution retains its original CLI/resource contract. API schemas are available in an expandable section.

**Start run is explicit execution authorization.** It creates a new bounded resource session with your frozen question, authorship, context, configuration and implementation identity. Defaults permit up to 24 initial research calls, three initial image inspections, four development choices, three revision inspections, and one optional eight-call research session (42 Qwen calls; 688,128 total reserved tokens at 16,384 per call). Three initial FLUX studies and at most three subsequent images use the selected `flux_base4b_study_512_v1` profile within a 120-minute window with a five-minute reserve. Each of three development actions chooses research or rendering; the final choice pauses or stops. New runs use online collections only, with at most 64 source requests and 16 acquisitions across initial and reopened research. Initial images plus development actions must total at most 12. The local reference-library selector, index discovery and index-selection request fields have been removed. Shared retrieval and preserved reference files remain available to historical inspection and separate continuation/CLI workflows. No paid API or training is admitted. Artistic adequacy of a question remains an operator judgment.

Panel workers queue one pipeline at a time across mounted workspaces. This queue coordinates panel-started runs; separately launched CLI workloads retain their existing resource locks. Closing the page does not stop its worker. **Stop run** appears beside active studio runs in the Runs table, under their recent-inquiry cards, and in the selected run’s heading, which stays visible while scrolling. Clicking any of these buttons sends one stop request and changes its controls to **Stopping…** until the worker settles. It preserves completed evidence and prevents the next dispatch; it does not interrupt an admitted model call or acquisition. A failed request displays the error and allows another click. Completed and failed runs do not offer this control. A queued stop takes effect when the worker obtains its slot. Repeated submission of the same unchanged request is idempotent. Failed, interrupted and partial runs keep their evidence; uncertain charged work is never automatically retried. Research can end without a committed direction or stop on a rejected response, so images are not guaranteed. A terminal research outcome without a hypothesis is marked **partial**, with its specific stop reason. Call totals come from the resource ledger. New research plans retain earlier candidates, block repeated remote queries, enter one bounded synthesis checkpoint after six actions without new evidence or a new draft/commit when leads exist, and reserve the final three actions for synthesis (or an explicit unresolved stop). The checkpoint uses the remaining original budget and cannot restart. See the [representative process acceptance gate](../operations/2026-09-09_live_process_acceptance.md) for verification of actual browser-to-render runs. Saved render instructions are checked against the pinned local FLUX tokenizer at draft and commit, before rendering. The time limit gates new work and cannot forcibly end an already admitted call.

The separate **Prepare** controls freeze inputs and are distinct from execution. For autonomous development, set `render_config.output_dir` to the exact output directory displayed in the form. Failed preparations retain any already written evidence; choose a new ID instead of overwriting it. Continued inference needs the existing explicit resource authorization, immutable inputs and admitted budget. The UI preserves model-authored artistic instructions and explicitly selected render settings. Panel-generated images do not create pairwise review collections.

Refresh an already-open panel after this update. Full-run HTTP submissions explicitly supply `development_steps` and `development_research_steps`; stale forms missing either field are rejected before worker creation so the old displayed budget cannot authorize larger new defaults.

The A/B review UI and dedicated run/workflow comparison engines are removed. Existing review stores and shared provenance contracts remain readable by lineage, continuation and dataset code. No historical image, raw response, review, immutable input or ledger was deleted. See the [retirement and verification record](../operations/2026-09-08_dev_panel.md).

Research steps now expose readable **Prompt sent to Qwen**, **Response from Qwen**, and **Tool response** sections. Expand the prompt to inspect its saved system instructions, admitted user context and image-input records; response format requirements have their own disclosure. Rejected or malformed replies retain their original text, and missing records are labeled instead of reconstructed. Images show the saved FLUX prompt alongside the output, seed, size and source IDs. Planned generations without images retain their prompts and any recorded failure. Raw JSON remains optional supporting evidence. These views read existing artifacts without changing frozen runs or launching inference.

Software verification covers fixture execution, read-only browsing, workspace isolation and form request contracts. It does not establish artistic improvement; the next artistic evidence gate still requires an actual developed work and independently attributed assessment.

New v10 runs return invalid hypothesis arguments as bounded tool feedback. If a later response is unrecoverably rejected after a valid commitment, the panel renders only earlier committed directions and reports a partial result with the rejection filename/error. The failed original run is not automatically resumed. See the [nested-hypothesis correction](../operations/2026-09-09_nested_hypothesis.md).

The [study-development protocol](../operations/2026-09-09_studies_before_commitment.md) applies to new full panel runs. Research exposes each study's operation, reason and difference from earlier studies; Development follows image-grounded observations through the [bounded development cycle](../operations/2026-09-09_development_cycle.md). Its counts come from frozen limits and saved records, including while a run is queued or incomplete. Open decision details and unchanged branch images survive live refreshes. Fewer than three realized studies or an incomplete planned image set prevents artistic selection and leaves a partial result. Seed variants do not satisfy the distinct-study requirement. New budgets include repeated development and optional reopened research; old frozen runs are unchanged. A model-requested review pause creates no human judgment or automatic continuation. Explicit `study_development: false` API requests are rendering diagnostics, not this full process.
