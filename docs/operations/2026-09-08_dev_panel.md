# Development panel revision — 8 September 2026

At the user's request, Kusama is presented as a minimal developer panel rather than a run-comparison interface. The panel now separates Runs, Development, Research, Sources, and Tools & system, with workspace selection, searchable run records, progressive images and expandable technical details. See the [panel workflow](../workflows/dev_panel.md).

The A/B and pool-review routes, UI controls and browser tests were removed. Dedicated comparison code was removed: comparison modes and schedules, common-parent development comparison and its baselines/adapter, E0 planning/execution/recovery, and the Phase 1 evaluation harness. Their dedicated tests, workflow configuration and current protocol guides were removed. New creative runs no longer register a comparison schedule. CLI commands `compare`, `development-compare`, `e0`, `evaluate` and `eval` are no longer available.

Shared immutable evidence helpers now live in `evidence.py`, the read-only resource authorization helper in `resource_snapshot.py`, and the budgeted renderer used by content diagnostics in `renderer_session.py`. This preserves standalone development, research, content diagnostics, dataset lineage and learning eligibility without importing deleted comparators. Existing review/provenance storage remains for historical records and continuation/dataset compatibility; individual edit measurements and parent/child lineage remain part of development.

Saved images, raw responses, original inputs, ledgers, reviews and failure records remain untouched. Older dated handoffs describe the code and capabilities present at their timestamps; references to removed comparison guides now lead here. Historical source specifications remain proposals, not the current implementation. Existing frozen execution plans can reject the changed implementation identity; they are not migrated or silently resumed.

The panel exposes existing continuation preparation, explicit dispatch, observations, decisions and studio selection. It also exposes native research/development planning and read-only source, resource and memory inventories. Other CLI workflows are available through their exact help entry points and guides. Browsing does not open writing resource or memory stores, launch model calls, write human judgments or train models.

This is a software and interface change. Artistic improvement and learned advantage remain unestablished. The next artistic evidence gate is a consequential artistic problem developed into saved work, followed by an independently attributed assessment under an explicitly authorized resource contract.

Browser checks covered the desktop and 390-pixel layouts, workspace navigation, saved continuation controls, and loaded whole/detail source images. ## Question-led home screen and run workspace

The follow-up request makes authoring an open-ended question and starting a run the central UI action. `panel_runs.py` joins existing independent research and research-render engines under a new frozen resource contract. The native form records question authorship and context, named profile, explicit call/image/time limits and opt-in collection access. Durable submission identities prevent duplicate dispatch; panel workers serialize across workspace mounts. Cooperative stopping preserves completed outputs and prevents the next dispatch. No research-quality score or invented human judgment is added.

Each run now has Overview, Research, Images, Activity and Files & logs tabs, recursive contained artifact access, inline text/image previews, model directions, reference evidence, prompt/lineage details, progress polling and failures. Legacy runs retain their saved files and evidence even where they lack an independent research trail. Source evidence remains explicitly attributed. The new question-led pipeline does not register comparison collections.
